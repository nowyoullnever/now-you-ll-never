# Preview playback (P02.9 — IMPLEMENTATION COMPLETE / EXTERNAL REVIEW PENDING)

`PreviewEngine` uses a fixed-capacity SPSC control-to-audio command ring. `InstallSource`, `ClearSource`, Play, Pause, Stop, Return, Seek, gain and mute are consumed only at audio block boundaries. A full ring returns an observable `QueueFull` result; the audio callback never allocates, locks, waits, reads files, logs, calls UI, or changes `shared_ptr` ownership.

The audio thread exclusively owns the active raw PCM pointer, generation, transport state, persistent fractional source cursor, output-rate conversion and smoothed gain. It publishes UI state through a fixed-capacity reverse SPSC queue: it writes a complete `TransportSnapshot` into an unpublished slot, then release-publishes the write index. The UI acquire-consumes only completed slots and keeps its latest complete snapshot. The queue has one reserved slot; when full, the callback drops the newest observation without allocating, waiting, locking or changing canonical transport state. PCM ownership stays on the control thread: a new source is retained before its raw pointer is put in the command queue; if command publication fails, that newly retained owner is rolled back. After audio acknowledgement of a replacement/clear generation, `Maintain()` releases superseded PCM outside the callback.

Preview gain is 0–200% (default 100%). Non-zero changes use deterministic per-sample smoothing; zero gain and mute contribute exactly zero, and mute retains the configured gain. The INBOX provides mouse and keyboard-accessible Preview Volume control, Play/Pause, Stop, Return and Mute controls. Playhead and elapsed time use the published source-frame position, not wall-clock time.

Standalone starts from silence and adds preview only while Playing. Plugin input remains bit-exact passthrough whenever preview is unavailable, stopped, paused, muted, or at zero gain. While preview is active, finite preview is mixed then clamped to [-1, 1] to prevent non-finite/uncontrolled full-scale output; this does not apply to inactive passthrough. `OPEN-AUDIO-01` remains OPEN pending real-host validation. Selection, loops, export and device settings remain out of scope.
